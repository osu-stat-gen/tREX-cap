tRexCAP: A Divide and Conquer Strategy for Recapitulating Whole Genome 3D Structure Using Hi-C Data

Introduction

The spatial organization of the genome is a critical determinant of cellular function, yet its complex architecture cannot be fully captured through linear sequencing alone. Hi-C technology overcomes this limitation by capturing chromosomal conformational information between loci. Translating the resulting 2D proximity matrices into physical 3D models enables the identification of spatial “neighborhoods,” revealing how non-coding genetic variants exert regulatory influence over vast genomic distances.

tRex-CAP (Cut and Paste) is designed to reconstruct whole-genome, three-dimensional structures from Hi-C data. The method employs a divide-and-conquer strategy to manage the complexity of genomic data: first, each chromosome is partitioned into n overlapping blocks; second, the tRex algorithm reconstitutes the 3D structure of each block independently; and finally, these local structures are “pasted” together to form a global model while preserving the structural rigidity of the individual blocks.

tRex-CAP algorithm consists of two steps. The first step is Cut where the entire contact matrix is partitioned into n blocks (with overlaps), and tRex algorithm is run on each block to obtain its respective structure. The second step is Paste where all blocks are merged into one structure using isometric transformations to preserve the structure of each block while matching them at the overlapping loci.

We illustrate the usage of these functions in the following sections.

  • breaks: A vector that describes the indices of pre-specified cut points. If unspecified, equal block size cuts will be used.
  • CPU: Integer specifying the number of cores for parallel MCMC execution.
  • save_mcmc: Whether to save the posterior samples generated during the MCMC step.
  • mcmc, burn: The number of HMC iterations and burn-ins, respectively.
  • thinning: Thinning rate. For example, a thinning rate of 10 means every 10th HMC iteration is saved as posterior samples.
  • jump: The initial standard deviations for parameters updated via Metropolis-Hastings.
  • leapfrog.L, leapfrog.e: The initial number of leapfrog steps and intial epsilon for HMC.
  • target.accept The target acceptance rate.
  • tuning_control: Tuning control for HMC. See below for details.
  • method.type: The method for for reconstructing each block. One of tRex, tPAM and bn.

Tuning Control

We do a five phase tuning. Phase 1 adapts the number of steps (L) and the step size (epsilon), phase 2 runs the chain, phase 3 adapts the step size (epsilon), phase 4 runs the chain, and phase 5 adapts the Metropolis-Hasting jump parameters.

The tuning control is a list comprising of iter, block_size and max_cycle. The iter parameter controls the number of iterations for each phase. Here, the block_size parameter controls how often acceptance rates are reported and how frequently hyperparameter adjustments occur according to parameter acceptance rates. The max_cycle parameter determines how many times the algorithm goes through the phases. Between cycles, the structure is reset but hyperparameter settings are retained. By default, the settings for tuning_control are retained. Below is an example of the tuning_control used for the sample data.

control_trex <- list(
  iter = c(500, 500, 500, 500, 500),
  block_size = c(10, 10, 10, 10, 10),
  max_cycle = 1
)

Output

Cut function returns the sturcture of each block and other parameters intended for Paste.

Paste

Pates function combines structures obtained in Cut step through rigid transformations.

Arugments

  • contact: The same contact matrix used in Cut.
  • cutresult: The result from a Cut() call.
  • CPU: Integer specifying the number of cores for parallel MCMC execution.

Output

Paste returns an n by 3 matrix of the estimated coordinates.

Example

Here we provide an example for tRex-CAP. For simplicity, we use the first 100 loci in our example with no bias matrix.

example_data_short <- example_data[1:100, 1:100]
CutRes <- Cut(
            contact = example_data_short, 
            block_size = 25, 
            noverlap = 1, 
            CPU = 1,
            mcmc = 1000,
            burn = 1000,
            thinning = 1,
            target.accept = 0.95,
            tuning_control = control_trex
          )

On the 3303MHz AMD EPYC 7R32 CPU, without parallelization it took 14.7 seconds to execute the command above.

To paste the results, run the following script:

PasteRes <- Paste(
              contact = example_data_short,  
              cutresult = CutRes, 
              CPU = 1
            )

Simulation

Here we briefly describe our approach to simulation in the paper.

Simulation Function

For a known structure S, we simulate the data based on either Poisson or negative binomial distrubtion. Possible parameters includes pi for zero inflation percentage, p for overdispersion paramter for negative binomial distribution, and random for the presence of random effect.

gen_contact <- function(S, family = "poisson", pi = 0, p = 0.75, random=FALSE) {
    # S matrix: coordiantes of the loci
    # family: poisson or NB
    # pi: zero inflation percentage: 0, 0.05, 0.15, 0.25, or 0.5
    # p overdispersion factor for NB: 0.5, 0.75, or 0.9
    # family='poisson' or 'nb'
    ns <- nrow(S)
    nI <- ns * (ns - 1) / 2
    alpha0 <- 4  # original is 2
    alpha1 <- -1.2
    dist_S <- dist(S)
    c1 <- matrix(nrow = ns, ncol = ns, 0)
    # dist is the lower triangle matrix
    # mu vector
    #no random component
    mu <- exp(alpha0 + alpha1 * log(dist_S))

    if (random) {
        NoiseU2 <- rnorm(nI, sd = sqrt(0.03))
        X <- rnorm(ns, sd = sqrt(0.1))
        temp <- matrix(rep(X, ns), ncol = ns, byrow = T)
        X_mat <- as.vector((temp + t(temp))[lower.tri(temp)])
        mu <- mu + X_mat + NoiseU2
        mu[mu < 1e-6] <- 1e-6
    }

    if (family == "poisson") {
        counts <- rzipois(nI, lambda = mu, pstr0 = pi)
    } else {
        counts <- rzinegbin(nI, size = mu * p / (1 - p), munb = mu, pstr0 = pi)
    }
    c1[lower.tri(c1)] <- counts
    return(c1)
}

Simulation

Below is the script we used for simulation.

require(VGAM)
require(reticulate)
require(splines)

# settings
family <- "poisson" # or nb for negative binomial 
pi <- 0 # zero-inflation parameter: options used in manuscript: 0, 0.05, 0.15, 0.25, 0.5
p <- 0.75 # overdispersion parameter: options used in manuscript: 0.5, 0.75, 0.9
random <- TRUE # random effect: if TRUE use random effect terms if FALSE do not use
nreps <- 1  # we set nreps to 100 in tRex-cap manuscript
seed = 2  # seed used in manuscript
cat("Simulating ", family, " with pi=", pi, ", p=", p, " random: ", random, " nreps = ", nreps, "\n", sep="")
set.seed(seed)

# build an informative output directory name
if (family == "poisson") {
  outdir <- paste0(
    "../siml_data/",
    family,
    "_pi_", pi,
    ifelse(random, "_ran", "_noran")
  )
} else {
  outdir <- paste0(
    "../siml_data/",
    family,
    "_pi_", pi,
    "_p_", p,
    ifelse(random, "_ran", "_noran")
  )
}

# create it if it doesn't exist
if (!dir.exists(outdir)) {
  dir.create(outdir, recursive = TRUE)
}


for (i in 1:nreps) {
    contact <- gen_contact(S, family = family, pi = pi, p = p, random = random)
    contact <- contact + t(contact)
    trex_name <- file.path(outdir, paste0("trex_", i, ".txt"))
    write.table(contact, trex_name, row.names = FALSE, col.names = FALSE, quote = FALSE)
}
